# 일과 · ilgwa

학습 주제나 전공 교재(PDF)를 입력하면 커리큘럼 기획부터 인터랙티브 슬라이드, 음성 수업(TTS), 핵심 암기노트, 실습 과제, 실전 모의고사까지 학습 전 과정을 자동 생성하는 AI 과외 플랫폼입니다.

- **서비스 데모**: https://algocean1204.github.io/SW-ilgwa/
  - 별도 로그인 없이 바로 체험할 수 있습니다. 파이썬, Rust, 운영체제 3개 과목의 슬라이드·음성 수업·모의고사·암기노트·과제가 미리 채워져 있습니다.
- **포트폴리오 웹**: https://algocean1204.github.io/SW-ilgwa/ptplo/
  - AI 파이프라인 설계 근거, 벤치마크 실측 데이터, 트러블슈팅 과정을 A4 10장 분량의 웹 문서로 정리했습니다.

## 팀 구성 및 담당 역할

2인 팀 프로젝트로 진행했으며, 트랜잭션 정합성이 중요한 비즈니스 코어 서버와 고부하 AI 추론 파이프라인의 수명주기를 분리해 설계·구현했습니다.

- **김태규 (AI 아키텍처 설계 · FastAPI 백엔드 · 모델 서빙)**
  - LangGraph 기반 기능별 AI 에이전트 파이프라인 설계 및 구현 (커리큘럼 기획, 슬라이드·노트·퀴즈·과제 생성, 모의고사 출제, 교재 RAG)
  - Modal B200 GPU 기반 Qwen3.6-27B Dense FP8(vLLM) 자체 서빙, 컨텍스트 분할 병렬 추론 및 콜드스타트 최적화
  - JSON 스키마 기반 `{{빈칸}}` 템플릿 구조 고정(강의 16종·시험 20종) 및 생성 산출물 사실·논리 검증 루프 구현
  - Qwen3-TTS 음성 클로닝(`float32` 정규화·비동기 큐 워커) 및 Whisper Large V3 Turbo 실시간 음성 인식(ASR) 파이프라인 구축
- **김나경 (Spring Boot 코어 서버 · 클라우드 인프라 배포)**
  - 사용자 인증(OAuth2), 코인 지갑 동시성 제어(조건부 원자적 `UPDATE`), 학습 데이터 및 전체 워크플로우 오케스트레이션
  - AWS(VPC, EC2, RDS, S3, CloudFront OAC) 아키텍처 설계 및 Terraform 기반 IaC 배포 자동화

![시스템 아키텍처](docs/architecture.png)

### 왜 Spring과 FastAPI로 서버를 분리했는가

사용자 인증·결제·학습 이력 관리처럼 트랜잭션 정합성이 중요한 코어 영역과, 대규모 비동기 I/O(`asyncio`) 및 GPU 추론·문서 파싱이 집중되는 AI 영역의 리소스 특성이 달라 서버를 분리했습니다.

- **프론트엔드 (React SPA)**: AWS S3 및 CloudFront(OAC)를 통해 배포하며, 생성된 슬라이드·음성 수업·모의고사·암기노트·과제 학습 인터페이스를 제공합니다.
- **코어 API 서버 (Spring Boot)**: 사용자 권한, 결제·코인 차감, 학습 상태 관리를 전담하고 비동기 작업(강의·시험 생성, 과제 채점)을 조율합니다.
- **AI 파이프라인 서버 (FastAPI)**: 외부 인터넷에 노출하지 않고 VPC 내부망에서 Spring 서버의 요청만 처리합니다. 복합 트랜잭션은 Spring이 맡고, 대용량 생성 산출물(슬라이드·노트·퀴즈·과제) 적재와 음성 대본 큐(`voice_script_queue`) 기록은 FastAPI에서 `asyncpg`로 직접 수행해 네트워크 왕복 지연을 줄였습니다.

## 핵심 엔지니어링 과제와 해결

### 1. 강의 생성 시간 76.8% 단축 (518초 → 120초) 및 강의당 $0.38 과금 구조

- **문제**: 15장 분량의 슬라이드와 퀴즈·노트·과제·음성을 앞 슬라이드 문맥 누적 방식으로 순차 생성하면 1강 완성에 518초(약 8분 38초)가 소요되었고, 뒤쪽 슬라이드로 갈수록 입력 문맥이 길어져 환각과 JSON 형식 깨짐이 발생했습니다.
- **해결**:
  - **Plan-First 기획 분리**: Claude Opus 4.6을 커리큘럼당 1회만 호출해 10~15개 슬라이드의 학습 목표·핵심 개념·시각 자료 타입을 먼저 고정했습니다.
  - **슬라이드별 독립 컨텍스트 병렬 추론**: 각 슬라이드가 이전 슬라이드 전문 대신 확정된 개요 슬롯만 참조하도록 분리하고, Modal B200 GPU에 올린 **Qwen3.6-27B Dense FP8** 모델을 vLLM Continuous Batching으로 동시 호출했습니다.
  - **콜드스타트 단축 및 시간 기반 과금**: 모델 가중치를 Modal 스토리지·메모리에 사전 로드해 초기 기동 지연을 **12.4초에서 0.8초(15.5배 가속)**로 줄였습니다. 외부 API 토큰 과금 대신 GPU 사용 시간(초당 $0.001736, 시간당 $6.25)만큼만 과금되도록 설계해 1강 생성 비용을 **$0.38**, 미사용 시 유지 비용을 **$0**으로 통제했습니다.

### 2. 양산 모델 선정: 왜 Qwen3.6-27B Dense FP8인가

상용 초거대 API(Opus/Sonnet) 단독 호출 시 발생하는 적자 구조를 해결하기 위해 오픈소스 모델 벤치마크를 거쳐 양산 엔진을 선정했습니다.

| 모델 | SkillsBench (코드·교육자료 구조화) | SWE-bench | MMLU-Pro | AIME | 아키텍처 특징 |
|---|---|---|---|---|---|
| Qwen3.5-35B-A3B | — | 70.0% | — | — | 이전 세대 MoE |
| Qwen3.6-35B-A3B (MoE) | 28.7 | 73.4% | — | 92.7 | 3B 활성 파라미터, 라우팅 분기 편차 발생 |
| **Qwen3.6-27B Dense FP8** | **48.2 (+68% 우위)** | **77.2%** | **86.2** | **94.1** | **전 파라미터 상시 활성, FP8 양자화 안정성** |

- **채택 근거**: 구조화된 교육 자료와 코드 예제 생성 능력을 좌우하는 SkillsBench에서 동급 MoE 모델 대비 **68%(48.2 vs 28.7)** 높은 점수를 기록했습니다. MoE 구조 특유의 라우팅 지연 편차(Jitter) 없이 27B 전체 파라미터가 상시 활성화되어 B200 GPU에서 일정한 응답 속도와 추론 품질을 보장합니다.
- **계층형 모델 라우팅**: 기획(Opus 4.6 1회) ↔ 본문 양산(Qwen3.6-27B) ↔ 질의응답·채점(Sonnet 4.6) ↔ 경량 교정·캡션(Kanana 2.1B)으로 역할을 분리해, 상용 초거대 모델 단독 호출 대비 연산 비용을 **76~79% 절감**하고 **약 27%의 운영 마진**을 확보했습니다.

### 3. `{{빈칸}}` 템플릿 전략과 내용 검증 루프

- **문제**: LLM에게 슬라이드 구조와 문항 형식을 자유롭게 작성하도록 맡기면 요청마다 구성과 난이도가 흔들리고, 형식은 맞아도 본문 정의나 코드 실행 결과가 틀리는 문제가 발생했습니다.
- **해결**:
  - **코드 기반 JSON 스키마 고정**: 별도 파인튜닝 비용($0) 없이 16개 강의 카테고리와 20종 모의고사 문제 유형의 JSON 스키마 골격을 코드로 미리 고정하고, AI는 지정된 `{{빈칸}}` 슬롯 데이터만 채우도록 제한했습니다.
  - **사실·논리 검증 및 원본 복구 루프**: 생성된 강의 JSON은 사실·논리 검증 노드가 1회 검사해 오류가 지적된 필드만 1회 선별 교정한 뒤 재검증합니다. 교정 과정에서 파싱이 실패하거나 슬라이드 인덱스가 깨지면 원본 데이터로 즉시 복구해 파이프라인 중단을 방지했습니다.

### 4. 품질 게이트 기반 하이브리드 교재 OCR & Qdrant RAG

- **문제**: 전공 교재 PDF를 단일 OCR로 처리했을 때 CPU ONNX(PP-OCRv5)는 문자오류율(CER) 48.8%, PaddleOCR-VL 단독은 페이지 CER 75.9%로 수식과 다단 표 구조가 깨져 검색 인덱스가 오염되었습니다.
- **해결**:
  - **하이브리드 파싱 및 후처리**: Marker로 1차 파싱한 뒤 페이지별 품질 게이트(신뢰도·빈 출력·수식 파손 여부)에 걸린 페이지만 MinerU로 재추출하고, Kanana-2 모델로 맞춤법 및 LaTeX 수식을 정규화해 후처리 구간 문자오류율(CER)을 16.047에서 **0.222(98.6% 감소)**로 낮췄습니다.
  - **Dense + Sparse 하이브리드 검색**: 600~1,200 토큰 단위로 분할한 교재 문단을 BGE-M3로 임베딩하여 의미 유사도(Dense 1024차원)와 전공 키워드 매칭(Lexical Sparse)을 결합해 Qdrant에서 검색·주입합니다.

### 5. 멀티 에이전트 병렬 모의고사 출제(ExamForge) 및 교차검증 루프

- **문제**: 다수의 시험 문항을 한 번의 호출로 생성하면 문항 수 누락, 특정 번호로의 정답 쏠림, 사실과 맞는 보기가 오답으로 포함되는 오류가 반복되었습니다.
- **해결**:
  - **단계별 분리와 병렬 생성**: 자료 분석 → 출제 계획 → 문제 생성(4개 에이전트 동시 병렬 처리) → 오답 구성 → 해설 작성 → 교차 검증의 6단계 LangGraph 워크플로우로 분리했습니다.
  - **정답 위치 사전 배정 및 선별 교정**: 생성 전 시드 기반으로 정답 인덱스를 균등 배정(`balanced_target_positions`)해 번호 편중을 없애고, 교차 검증에서 출처 이탈이나 복수 정답이 감지되면 해당 문항만 최대 3회 자동 교정(불가 시 재생성)합니다.

### 6. Qwen3-TTS `float32` 정규화·비동기 큐 분리 및 다단계 장애 폴백

- **오디오 텐서 정규화**: Qwen3-TTS 추론 출력(`float16`·비정규화 버퍼)을 그대로 16-bit PCM WAV로 변환할 때 발생하던 양자화 클리핑 잡음을 `np.clip(audio.astype(np.float32), -1.0, 1.0)` 정규화 파이프라인으로 해결했습니다. 참조 음성과 참조 문장을 함께 고정해 화자 유사도 **0.964~0.976**(반복 측정 표준편차 0.0006, 합성 음성 재인식 오류율 CER 0.010~0.019)을 달성했습니다.
- **비동기 DB 큐 워커**: 슬라이드 생성 그래프는 음성 대본 텍스트만 `voice_script_queue`에 저장하고 즉시 응답을 반환하며, 별도 TTS 워커가 대본을 40~120자 청크로 나눠 합성한 뒤 S3·미디어 URL로 제공합니다.
- **다단계 장애 폴백**: 주 경로(Modal GPU) 장애나 타임아웃 발생 시 작업 특성에 맞춰 Gemini / Claude(Sonnet·Opus) / OpenAI로 자동 우회하며, 폴백 모델 호출 시 출력 토큰 상한(16,384 클램프)을 적용해 규격 차이로 인한 400 오류를 방지했습니다.

## 파이프라인 흐름

### 1. OCR (교재 PDF → Qdrant 검색 인덱스)

```mermaid
flowchart TD
  pdf[PDF] --> classify[페이지 분류]
  classify --> extract[Marker 추출]
  extract --> gate[품질 게이트]
  gate -->|통과 / 전부 실패| post[후처리]
  gate -->|일부 실패| mineru[MinerU 재추출]
  mineru --> post
  post --> chunk[청킹]
  chunk --> embed[BGE-M3 임베딩]
  embed --> qdrant[Qdrant 저장]
```

텍스트 레이어 유무와 페이지 구조를 분류한 뒤 Marker로 1차 추출하고, 품질 게이트에서 실패한 페이지만 MinerU로 다시 추출합니다. Kanana-2 후처리와 600~1,200 토큰 청킹을 거쳐 BGE-M3(Dense 1024 + Sparse) 임베딩 후 Qdrant에 저장합니다.

### 2. 강의 생성 (ChapterStudio)

```mermaid
flowchart TD
  ctx[컨텍스트 준비] --> gen[산출물 생성]
  gen --> slides[슬라이드]

  gen --> save[저장]
```

학습 목표를 검증하는 코드 작성 과제와 루브릭(채점 기준)을 생성합니다. 학생이 제출한 과제 채점은 웹 요청 지연을 막기 위해 생성 그래프 밖의 비동기 스레드로 분리했으며, Claude Sonnet(실패 시 Gemini 폴백)이 채점한 점수(0~100점)와 피드백을 최대 3회 재시도 로직을 통해 Spring 서버로 콜백합니다.

### 6. 실전 모의고사 출제 (ExamForge)

```mermaid
flowchart TD
  src[자료 분석] --> plan[출제 계획]
  plan --> q[문제 생성]
  q --> dist[오답]
  dist --> ans[해설]
  ans --> verify[교차 검증]
  verify -->|통과| out[출력]
  verify -->|실패| repair[교정]
  repair -->|교정 가능| verify
  repair -->|불가| q
```

20종 문제 유형(한국어 9종, 영어 8종, 자격증 3종) 중 학습 자료에 맞는 출제 계획을 세우고, 4개 에이전트가 동시에 문항을 병렬 생성합니다. 오답 매력도와 참인 오답 혼입 여부, 출처 단어 일치도를 교차 검증해 통과하지 못한 문항만 최대 3회 교정하거나 재생성합니다.

### 7. 음성 수업 합성 (TTS) 및 실시간 음성 질문 (ASR)

```mermaid
flowchart TD
  slides[슬라이드] --> script[대본]
  script --> tts[Qwen3-TTS voice cloning]
  ref[참조음성] --> tts
  tts --> audio[음성파일]
```

슬라이드별 대본을 4섹션 구조(850~2,400자)로 생성하고 연속된 슬라이드 간 중복 인사말을 제거한 뒤, 40~120자 청크로 나눠 Qwen3-TTS로 합성합니다. 학습 중 학생의 음성 질문은 Silero VAD로 발화 구간을 자르고 Whisper Large V3 Turbo(CER 0.009, WER 0.030)로 전사해 슬라이드 문맥 기반 챗봇으로 전달합니다.
