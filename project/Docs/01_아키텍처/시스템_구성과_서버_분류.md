# 시스템 구성과 서버 분류

결제·인증(Spring)과 장시간 AI 추론(FastAPI·Modal GPU)을 서버 단위로 나눴다. 엔드포인트별 서버 배정은 [`엔드포인트_분류표.md`](../02_API/엔드포인트_분류표.md)에 있다.

## 배포 구성

```
클라이언트 (React SPA · Telegram · 소셜 로그인 SSO)
    → CloudFront (S3 정적 배포 · OAC)
    → Nginx (80/443)
    → Spring Boot (EC2, 결제·인증·API) ─ Redis (세션·캐시) · RDS PostgreSQL 16 · S3 업로드
    → FastAPI (EC2 t3.small, 사설 IP:8000) ─ Qdrant (Dense+Sparse) · RDS · S3 직접 적재
          ├─ Modal GPU: Qwen3.6-27B FP8·vLLM (B200, 슬라이드 8슬롯 병렬), Qwen3-TTS (H100), Whisper V3 Turbo, BGE-M3·reranker, Kanana-2 (교재 OCR 교정, B200)
          ├─ Claude API: Opus 4.6 (커리큘럼 설계, 1강당 1회), Sonnet 4.6 (사실·논리 검증, 채팅, 채점)
          └─ CPU 워커: Kanana Nano 2.1B + LoRA (알림 문구, llama.cpp Q4)
```

폴백은 커리큘럼 외 텍스트 작업 전부 Modal → Claude 순서다. TTS·ASR·임베딩은 Claude에 해당 API가 없어 Claude 폴백이 없다.

FastAPI 모듈은 Agent_orchestrator(비동기 Job·멱등 키·Spring 콜백), ChapterStudio_V1(강의·슬라이드·템플릿 75종), ExamForge_V1(모의고사 LangGraph 6단계), OCR_v1(교재 OCR·RAG), TTS_V2(음성 수업·문장 단위 합성), Chat_V1(강의 맞춤 Q&A·스트리밍), AssignmentGrader_V1(과제 채점·Sonnet VLM)로 나뉜다.

## 서버 분류

| 표기 | 서버 | Base URL | 역할 |
|------|------|----------|------|
| Spring | Spring Boot | `https://api.ilkwa.com/api` | 비즈니스 로직, 유저/인증/과외/결제/구독/캘린더/알림 |
| FastAPI | FastAPI | `https://ai.ilkwa.com/api` | AI 파이프라인, 커리큘럼 생성, 과제 채점, LLM 호출, Telegram 웹훅 수신, OCR(OCR_v1) |
| Modal | Modal GPU | (FastAPI가 invoke) | 자체 GPU 추론: Qwen3.6-27B FP8·vLLM(B200), Qwen3-TTS(H100), Whisper V3 Turbo(앱 `asr-whisper-v3-turbo`), BGE-M3·리랭커(앱 `ocr-bge-m3`, `OCR_V1_EMBED_BACKEND=modal` 기본. `local`이면 FastAPI 프로세스 안에서 돈다), Kanana-2(게이트 실패 쪽 교정, B200). FastAPI가 비동기로 호출하고 외부에 직접 노출하지 않는다 |
| Composite | Composite | (다중 서버 파이프라인) | 한 요청이 두 개 이상의 서버를 거치는 흐름 |
| Internal | Internal | VPC 내부 전용 (외부 노출 없음) | Spring↔FastAPI 서버 간 통신. `X-Internal-Token` 인증 |

## Composite 흐름

### Composite #1: POST /assignments/{id}/submit (과제 제출, zip/PDF/이미지 채점)

```
[클라이언트]
    │  multipart/form-data (.zip / .pdf / .png / .jpg / .jpeg / .webp 중 하나 첨부)
    ▼
Spring Boot  (/assignments/{id}/submit)
    │  1. JWT 검증 + 과제 존재 확인
    ▼
FastAPI  (Spring Boot가 파일 bytes 전달)
    │  1a. 외부 확장자 검증 + 경로 분기 (Python stdlib, FastAPI 수신 레이어)
    │
    │  ┌─ 1a-1. Content-Type + 외부 확장자 검사 ─────────────────────────────┐
    │  │   허용: .zip / .pdf / .png / .jpg / .jpeg / .webp                    │
    │  │   파일 크기 ≤ 20 MB                                                   │
    │  │   그 외 → 415 반환 + rejected_reason 기록                             │
    │  └──────────────────────────────────────────────────────────────────────┘
    │
    │  ┌─ 1a-2. zip 경로 ────────────────────────────────────────────────────┐
    │  │   외부 확장자 == .zip 일 때 수행                                       │
    │  │   ├─ 내부 파일 수 ≤ 30                                                │
    │  │   ├─ 내부 확장자 화이트리스트 (.pdf / .png / .jpg / .jpeg / .webp)    │
    │  │   ├─ 압축률 ≤ 100:1  (zip bomb 방어)                                 │
    │  │   ├─ 해제 후 총 용량 ≤ 100 MB                                         │
    │  │   └─ 경로 공격 (../) · 중첩 zip 차단                                  │
    │  │   통과 → 1b 단계 진행                                                  │
    │  │   실패 → 413/422 반환 + rejected_reason 기록                          │
    │  └──────────────────────────────────────────────────────────────────────┘
    │
    │  ┌─ 1a-3. 단건 경로 ───────────────────────────────────────────────────┐
    │  │   외부 확장자 == .pdf / .png / .jpg / .jpeg / .webp 일 때 수행        │
    │  │   ├─ 파일 크기 ≤ 20 MB  (1a-1에서 이미 확인, 재확인 생략 가능)         │
    │  │   └─ Content-Type(MIME) 일치 확인                                    │
    │  │   통과 → 1b 단계 진행                                                  │
    │  │   실패 → 413/415 반환 + rejected_reason 기록                          │
    │  └──────────────────────────────────────────────────────────────────────┘
    │
    │       rejected_reason enum 값: size_exceeded / invalid_ext /
    │       too_many_files / invalid_inner_ext / zip_bomb /
    │       uncompressed_size_exceeded / path_traversal / nested_zip /
    │       mime_mismatch
    │
    │  2. 제출 메타데이터 생성 (submission 테이블)
    │      └─ original_file_size, file_count, rejected_reason (통과 시 NULL) 기록
    │
    │  1b. PDF 처리 분기  ※ Python pypdfium2에서 처리.
    │      대상: 단건 .pdf 제출 또는 zip 내부 .pdf 항목 각각에 적용
    │      ├─ pypdfium2로 PDF 열기
    │      ├─ 페이지별 텍스트 레이어 존재 여부 감지
    │      │   ├─ 텍스트 있음  → 해당 페이지 텍스트 직접 추출 (OCR 스킵)
    │      │   └─ 텍스트 없음·빈 페이지  → 300 DPI 래스터화 → image bytes → 1c 투입
    │      └─ 혼합 PDF: 페이지별 분기 처리, 결과는 페이지 순서대로 병합
    │
    │  1c. 이미지 bytes → Sonnet 4.6 VLM 직접 처리 (OCR 레이어 없음)
    │      대상: 단건 이미지 제출 + zip 내부 이미지 + PDF 래스터화 결과물
    │      대상 아님: PDF 텍스트 레이어 직접 추출본 (1b에서 처리 완료)
    │      ※ VLM이 필기·도표·수식을 이미지 그대로 읽는다. overlay PDF는 만들지 않는다.
    │  3. 추출 텍스트·이미지 + 풀이 컨텍스트 → Claude Sonnet 채점 호출
    │  4. 채점 결과 (점수, 피드백, 취약점) 생성
    │  5. 결과를 Spring Boot REST 콜백으로 전달
    ▼
Spring Boot
    │  6. grade 테이블 저장
    │  7. submission 테이블 완료 상태 업데이트
    │  8. 알림 상태 저장 → 클라이언트 polling 또는 다음 요청 piggyback
    ▼
[클라이언트]  채점 결과 수신
```

> 외부 확장자 검증(1a)은 FastAPI 수신 레이어에서 Python stdlib으로만 한다. PDF 렌더링·텍스트 추출(1b)은 Python `pypdfium2`에서 한다. 2026-04-19 이전 설계는 이 자리에서 PaddleOCR ONNX → conf < 0.70이면 VLM fallback 순서였고, 지금은 VLM 직접 처리로 바꿨다. 검증 규칙은 [`Spring_API.md`](../02_API/Spring_API.md) 과제 제출 절에 있다.

#### 단계별 처리 주체

| 처리 주체 | 담당 단계 | 비고 |
|-----------|-----------|------|
| Python stdlib `zipfile` | 1a-1, 1a-2 검증 | FastAPI 수신 레이어 |
| Python `pypdfium2` | 1b PDF 렌더링·텍스트 추출 | |
| Claude Sonnet 4.6 VLM | 1c 이미지 판독 | OCR 레이어 없음 |
| Claude Sonnet | 3 채점 | FastAPI → Anthropic API |

> 채점 트리거는 배치 스케줄러(06/12/18/24시). 제출 즉시 채점하지 않으며, submission.status는 `pending`으로 유지된다.
> 채점 완료는 `POST /internal/submissions/{id}/ai-result` 콜백 경유. DLQ 5회 실패 시 submission.status가 `failed`로 전이된다.

### Composite #2: POST /assignments/{id}/submit/telegram (Telegram 제출)

> 이 경로에도 Composite #1과 같은 파일 검증(1a 단계)을 적용한다. 텔레그램 봇을 통한 제출도 .zip / .pdf / .png / .jpg / .jpeg / .webp 5종 외부 확장자를 받는다. FastAPI 수신 레이어에서 외부·내부 확장자, 용량, 파일 수, 압축률, 경로 공격을 먼저 검증한 뒤 Telegram 발송으로 넘어간다.
>
> L2 검증 추가 (2026-04-20): 파일 검증을 3-레이어로 늘렸다. L1 확장자 화이트리스트 통과 후, L2에서 제출 파일 유형이 과제의 `expected_input_type`과 일치하는지 검증한다. 불일치 시 `415 REJECTED_TYPE_MISMATCH` 반환. 상세는 [`Spring_API.md`](../02_API/Spring_API.md)의 `POST /assignments/{id}/submit/telegram` 에러 응답에 있다.

```
[클라이언트]
    │  REST JSON (과제 ID + Telegram 전달 요청)
    ▼
Spring Boot  (/assignments/{id}/submit/telegram)
    │  1. JWT 검증 + 텔레그램 연동 상태 확인 (telegram_account)
    │  2. 제출 메타데이터 생성 (submission 테이블)
    │  3. 내부 FastAPI 호출 (Telegram 발송 위임)
    ▼
FastAPI  (내부 호출)
    │  4. Telegram Bot API 호출
    │     - 과제 내용 + 제출 안내 메시지 포맷
    │     - 유저 Telegram chat_id로 메시지 발송
    │  5. 발송 결과 반환
    ▼
Spring Boot
    │  6. 발송 결과 submission 테이블 업데이트
    │  7. 클라이언트에 200 응답 반환
    ▼
[클라이언트]  제출 완료 확인
```
