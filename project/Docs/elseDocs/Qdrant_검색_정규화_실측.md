- 처음 로직: 추출 결과를 그대로 청킹하고 Dense 벡터 하나로 검색한다.
- 개선 로직: 페이지마다 정규화한 뒤 청킹하고, Dense와 Sparse 결과를 RRF(k=60)로 합친 상위 10개를 BGE-Reranker로 다시 매긴다. 서비스 `hybrid_search`와 같은 순서다.
- Top-3 향상은 하이브리드 검색(37.5% → 52.1%)과 리랭커(52.1% → 65.8%)에서 나왔다. 키워드형 질의의 Top-1 적중률은 12.5%에서 64.2%로 올랐다.
- Marker 출력은 머리글과 쪽 번호가 이미 빠진 상태라 정규화가 바꾼 페이지가 0/36이었다. 머리글·줄바꿈이 남는 텍스트 레이어 입력에서는 정규화만으로 Top-3가 28.3%에서 32.5%로 올랐다.

## 2. 측정 환경

| 항목 | 값 |
|---|---|
| 장비 | Apple M4 Pro, 메모리 48GB, macOS (MPS) |
| 추출 | marker-pdf 기본 설정 |
| 청킹 | 서비스 `OCR_v1` SectionChunker (600~1,200 토큰, tiktoken cl100k_base) |
| 임베딩 | BAAI/bge-m3, fp16. Dense 1024차원(L2 정규화, 벡터 길이 1.0 확인), Sparse lexical weights |
| 저장·검색 | qdrant-client 인메모리 모드. Dense는 COSINE, Sparse는 기본 설정 |
| 결합 | 서비스 `qdrant_store._rrf_merge`와 같은 식. Dense·Sparse 각각 top_k×2개를 받아 `1/(60+순위)`를 더한다 |
| 재정렬 | BAAI/bge-reranker-v2-m3. 서비스 `bge_reranker.py`와 같이 RRF 상위 10개(`OCR_V1_RERANK_TOP_K`)를 점수 순으로 다시 매긴다. Mac에서는 서비스와 같이 fp32 |

## 3. 테스트셋과 질의

- 교재형 PDF 36쪽, 8장 80절, 문단 480개. 쪽마다 머리글("AI 서비스 개발 실무 · 실습 교재")과 쪽 번호("- n -")가 있고, 문단이 쪽을 넘어 이어진다.
- 4쪽마다 1쪽은 스캔본으로 바꿨다(9쪽, 25%).
- 질의는 문단 120개를 표본으로 뽑아 두 가지로 만들었다(총 240개).
  - 키워드형: 그 문단에서 IDF가 높은 단어 4개
  - 문장형: 그 문단의 가장 긴 문장에서 세 번째 단어마다 하나씩 뺀 것
- 정답 청크: 대상 문단의 가운데 30자를 포함하는 청크(rapidfuzz partial_ratio 90 이상). 질의 하나에 정답 청크는 하나다.
- 지표: Hit@k(정답 청크가 상위 k개 안에 있는 비율, k = 1 · 3 · 5 · 10), MRR@10.

## 4. 로직

### 4-1. 처음 로직

```python
combined = "".join(f"

<!-- page:{p['page_num']} -->

" + p["markdown"] for p in pages)
chunks = await SectionChunker().chunk(combined, pages)
client.query_points(col, query=q["dense"], using="dense", limit=top_k)
```

### 4-2. 개선 로직

```python
# 페이지별 정규화: 쪽 번호·반복 머리글 제거 → 하이픈 복원 → 끊긴 문단 병합 → 표 열 맞춤 → 수식 표기 통일
clean = [dict(p, markdown=await run_all(p["markdown"])) for p in pages]
chunks = await SectionChunker().chunk(combine(clean), clean)
d  = client.query_points(col, query=q["dense"], using="dense", limit=top_k * 2).points
sp = client.query_points(col, query=SparseVector(**q["sparse"]), using="sparse", limit=top_k * 2).points
score[id] += 1 / (60 + rank)   # 두 결과의 순위를 더해 정렬, 상위 10개
scores = reranker.compute_score([[query, chunk] for chunk in top10], normalize=True)   # 다시 매김
```

Dense(코사인 유사도)와 Sparse(키워드 가중치)는 점수 범위가 달라 그대로 더할 수 없다. 그래서 점수 대신 순위로 합친다.

## 6. 해석과 한계

- 리랭커는 Top-1을 가장 크게 올렸다(Marker 34.6% → 59.6%). 찾은 정답을 대부분 1위로 올린다.
- 리랭커는 RRF 상위 10개 안에서 순서만 바꾼다. 그래서 Top-10은 하이브리드와 같은 70.8%이고, 이 값이 지금 구성의 상한이다. 나머지 29.2%는 정답 청크가 후보 10개에 들지 못한 경우다.
- 서비스는 강의 생성에 상위 10개(`top_k=20` 요청, 후보 10개), 커리큘럼 · 기본 검색에 상위 5개를 넣는다.
- 정규화는 추출기가 잡음을 남길 때 효과가 있다. Marker 경로에서는 바꿀 것이 없었다.
- 머리글 제거는 "한 페이지 안에서 2번 이상 반복되는 짧은 줄" 규칙이라, 쪽마다 한 번씩 나오는 교재 머리글은 지우지 못했다. 쪽을 넘어 이어지는 문단도 페이지별 처리라 붙이지 못한다.
- 테스트셋은 합성 교재이고 질의는 규칙으로 만들었다(키워드 4개, 단어를 뺀 문장). 실제 학생 질문보다 거칠고, 정답 청크를 하나로만 쳐서 엄격하다.
- 2026-11-02 측정(리랭커 제외)은 하이브리드 Top-3가 52.5%였다. 측정 환경을 다시 만들어 돌린 이번 값은 52.1%로 0.4%p 차이가 난다.
