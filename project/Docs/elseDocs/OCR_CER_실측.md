# 교재 OCR 글자 오류율(CER) 실측

측정일 2026-11-02. 재현 스크립트는 `project/benchmarks/ocr_cer/`, 결과 요약은 `project/benchmarks/ocr_cer/results/summary.json`에 있다.

## 1. 요약

| 경로 | 전체 CER | 스캔 페이지 CER |
|---|---|---|
| Marker → 품질 게이트 → 실패 쪽만 MinerU (서비스 경로) | 0.003 | 0.009 |
| Kanana 교정을 전 페이지에 적용 | 0.437 | 0.414 |

- 교재 30쪽(텍스트 22쪽, 스캔 8쪽)에서 최종 CER 0.003, 스캔 페이지 0.009였다.
- Kanana 교정을 모든 페이지에 걸면 30쪽 모두에 원문에 없는 설명 문장이 붙어 CER이 0.437로 올랐다. 그래서 교정은 품질 게이트에 걸린 페이지에만 쓴다.
- 이전에 쓰던 PP-OCRv5는 Kanana 후처리 뒤에도 CER 0.492 → 0.408로 거의 줄지 않았다(crop 10건 PoC, 2026-04-20). 측정 단위와 데이터가 달라 이번 수치와 배율로 비교하지는 않는다.

## 2. 측정 환경

| 항목 | 값 |
|---|---|
| 장비 | Apple M4 Pro, 메모리 48GB, macOS |
| Python | 3.12 (엔진별로 가상환경을 나눔) |
| 1차 추출 | marker-pdf 기본 설정 |
| 재추출 | MinerU 2.7.6, `-b pipeline -m auto -l korean` |
| 교정 모델 | kakaocorp/kanana-nano-2.1b-instruct (MLX, 2.1B) |
| 품질 게이트 | 서비스 코드 `OCR_v1/quality` 그대로, 통과 기준 0.7 |
| 소요 시간 | Marker 435초, MinerU 370초, Kanana 교정 30쪽 931초 |

## 3. 테스트셋

- A4 30쪽 교재형 PDF. 본문은 프로젝트 문서의 한국어 문단에서 뽑았고, 표 10쪽과 수식 10쪽이 섞여 있다.
- 4쪽마다 1쪽을 이미지로 바꿔 스캔본을 만들었다(8쪽, 약 27%). 150dpi, 0.6~0.9 흐림, 가우시안 잡음, JPEG 압축. 2쪽은 110dpi로 더 낮췄다.
- 정답(GT)은 이미지로 바꾸기 전 디지털 페이지의 텍스트다.
- 스트레스 세트: 같은 30쪽에서 스캔 8쪽만 90dpi, 강한 잡음, JPEG 35로 바꿨다.

## 4. CER 계산

1. 정답과 추출 결과를 NFKC로 정규화한다.
2. 마크다운 이미지, HTML 태그, LaTeX 명령을 뺀다.
3. 한글, 영문, 숫자만 남긴다. 공백과 기호는 비교하지 않는다.
4. 문자 단위 편집거리를 정답 길이로 나눈다. 페이지별 값을 평균한다.

## 5. 과정과 로직

### 5-1. 처음 로직: 단일 OCR + 후처리

PP-OCRv5로 글자를 읽고 Kanana로 교정했다. 음절이 이미 빠진 출력은 교정 모델이 되살리지 못해 CER이 0.492에서 0.408로만 줄었고, 10건 중 1건에서 원문에 없는 내용이 생겼다.

### 5-2. 개선 로직: 이중 추출 + 게이트 + 선별 교정

```
PDF → Marker 추출 → 품질 게이트 ─ 통과 → 후처리(쪽 번호·하이픈·문단·표·수식 정리) → 청킹
                                 └ 실패 → MinerU 재추출 → Kanana-2 교정 → 후처리 → 청킹
```

- 품질 게이트는 페이지마다 문자 오염(30%), 읽기 순서(25%), 표 무결성(25%), 수식 보존(20%)을 가중 평균한다. 0.7 미만이면 실패다.
- 실패한 페이지만 MinerU로 다시 추출하고, 그 결과에만 Kanana-2 교정을 건다. 통과한 페이지는 교정하지 않는다.
- 모든 페이지가 실패한 문서(스캔본)도 MinerU로 보낸다.

## 6. 결과

### 6-1. 본 세트 (30쪽)

| 경로 | 전체 | 스캔 8쪽 | 텍스트 22쪽 |
|---|---|---|---|
| Marker 단독 | 0.003 | 0.009 | 0.001 |
| MinerU 단독 | 0.011 | 0.026 | 0.005 |
| 서비스 경로 (Marker → 게이트 → 실패 쪽만 MinerU) | 0.003 | 0.009 | 0.001 |
| Kanana 교정 전 페이지 적용 | 0.437 | 0.414 | - |

- 게이트에 걸린 페이지는 0쪽이었다. 그래서 서비스 경로의 결과는 Marker 단독과 같다.
- Kanana 교정을 전 페이지에 걸었을 때는 교정 대신 문단 앞에 설명 문장을 덧붙였다. 원문과 입력 어디에도 없는 6글자 조각이 5%를 넘은 페이지가 30쪽 중 30쪽이었다.

### 6-2. 스트레스 세트 (저화질 스캔)

| 경로 | 전체 | 스캔 8쪽 |
|---|---|---|
| Marker 단독 | 0.038 | 0.140 |
| MinerU 단독 | 0.263 | 0.971 |

- 저화질 스캔에서는 Marker도 CER 0.140까지 올랐고, MinerU 단독은 대부분 읽지 못했다.
- 이 세트에서도 게이트 실패는 0쪽이었다.

## 7. 한계

- 품질 게이트는 표·수식 구조와 문자 오염(한자 비율)을 보고, 글자 오류율 자체는 보지 않는다. CER 0.14인 스캔 페이지도 통과했다.
- 테스트셋은 프로젝트 문서로 만든 합성 교재다. 실제 전공 교재의 다단 편집, 손글씨, 복잡한 수식은 포함하지 않았다.
- 교정 모델은 kanana-nano-2.1b-instruct로 쟀다. 서비스 설정의 Kanana-2 배포 모델과 크기가 다르다.

## 8. 재현

```bash
cd project/benchmarks/ocr_cer
./run.sh                 # 기본 본문: project/Docs
./run.sh <md 폴더 ...>   # 다른 문서로 교재를 만들 때
```

- 이번 측정의 본문은 공개하지 않는 내부 문서였다. 기본 본문(project/Docs)으로 돌리면 테스트셋이 달라져 수치가 조금 다를 수 있다.
- 측정 방법(테스트셋 구성, 게이트, CER 계산)은 스크립트에 그대로 들어 있다.
