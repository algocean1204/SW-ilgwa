# 디자인 시스템 가이드 (Frontend Guide)

화면을 추가하거나 수정할 때 이 문서를 먼저 읽는다. 디자인 시스템, 레이아웃 규칙, 컴포넌트 사용 기준, 모션, 접근성, 검수 명령어를 한 곳에 정리한 가이드다.

### 1.2 시맨틱 별칭 레이어

새 페이지 작업은 아래 별칭을 우선 사용한다. 도메인 특수 케이스만 원시 토큰을 직접 쓴다.

```css
:root {
  --surface-page:   var(--bg);
  --surface-card:   var(--paper);
  --surface-strong: var(--surface);
  --surface-subtle: var(--surface-muted);

  --text-primary:   var(--ink);
  --text-secondary: var(--ink-2);
  --text-tertiary:  var(--ink-3);
  --text-muted:     var(--muted);

  --border-default: var(--line);
  --border-soft:    var(--line-2);

  --accent-primary: var(--grass-1);
  --accent-strong:  var(--grass-2);
  --accent-soft:    var(--grass-wash);

  --state-danger:      var(--coral);
  --state-danger-bg:   var(--coral-wash);
  --state-warning:     var(--honey);
  --state-success:     var(--grass-2);
  --state-success-bg:  var(--grass-wash);
}
```

## 2. 색상 사용 규칙

- 앱 화면 배경: `--surface-page`만 사용한다
- 카드 기본 배경: `--surface-card`만 사용한다
- 메인 CTA 배경: `--accent-primary`만 사용한다
- 성공 상태: `--state-success` 또는 `--state-success-bg`만 사용한다
- **핑크(coral)**: 경고, 마감 임박, 삭제, 오답에만 사용한다
- **옐로(honey)**: 코인, 보상, 배지 강조, 주의 문구에만 사용한다
- 하드코딩 HEX는 금지다. 예외: Google 로고색, Kakao 브랜드 옐로, Telegram 브랜드 블루
- 순검정(`#000`, `#000000`) 하드코딩은 0건이어야 한다
- 중복 토큰 재선언 금지(`--paper`, `--coral-wash`, `--coral-soft` 등)

## 3. 타이포그래피 규칙

### 3.1 기본 폰트 스택

```css
font-family: "Geist Variable", "Pretendard Variable", "Noto Sans KR", sans-serif;
```

### 3.2 `.script` 포인트 폰트 허용 범위

- 랜딩 히어로
- 인증 왼쪽 브랜드 장면
- 페이지 제목 중 1개 단어 강조 (앱 내부 최대 1회)
- `LessonEditor`, `Settings`, `Report`, `MemoryNotes`, `AdminConsole`에서는 사용하지 않는다

### 3.3 타이포 스케일

| 용도 | 크기 | 굵기 | 자간 | 줄간격 |
|---|---|---|---|---|
| Eyebrow | `11px` | `700` | `0.14em` | `1.4` |
| Page Title L | `32px` | `800` | `-0.03em` | `1.15` |
| Page Title M | `28px` | `800` | `-0.03em` | `1.18` |
| Section Title | `20px` | `800` | `-0.02em` | `1.25` |
| Section Subtitle | `13px` | `500` | `0` | `1.6` |
| Body | `13px` | `500` | `0` | `1.6` |
| Label | `12px` | `700` | `0` | `1.45` |
| Tiny Label | `10px` | `700` | `0.08em` | `1.3` |
| Metric | `28px` | `800` | `-0.03em` | `1.1` |
| Metric Compact | `22px` | `800` | `-0.02em` | `1.1` |

- 페이지 제목은 `32px` 또는 `28px` 둘 중 하나만 사용한다
- 보조 설명 텍스트는 `13px` 기본으로 고정한다
- 카드 안 작은 캡션은 `10px` 또는 `11px`만 사용한다
- `14px`, `15px`, `17px` 제목을 여기저기 섞어 쓰지 않는다

## 4. 간격 · 반경 · 그림자 · 보더

### 4.1 간격 스케일

이 값 외 사용 금지.

| 이름 | 값 | 사용처 |
|---|---|---|
| `space-4` | `4px` | 아이콘과 라벨 미세 간격 |
| `space-6` | `6px` | 칩 내부 |
| `space-8` | `8px` | 컴팩트 리스트 |
| `space-10` | `10px` | 폼 컨트롤 사이 |
| `space-12` | `12px` | 기본 카드 내부 최소 간격 |
| `space-14` | `14px` | 카드 섹션 사이 |
| `space-16` | `16px` | 기본 카드 패딩 |
| `space-18` | `18px` | 페이지 섹션 내부 간격 |
| `space-20` | `20px` | 표준 섹션 분리 |
| `space-24` | `24px` | 메인 블록 분리 |
| `space-28` | `28px` | 메인 히어로 패딩 |
| `space-32` | `32px` | 큰 섹션 패딩 |

### 4.2 라운드 스케일

이 값 외 사용 금지.

| 이름 | 값 | 사용처 |
|---|---|---|
| `radius-8` | `8px` | 칩, 입력창, 작은 버튼 |
| `radius-10` | `10px` | 세컨더리 버튼 |
| `radius-12` | `12px` | 기본 카드 |
| `radius-14` | `14px` | 메인 섹션 카드 |
| `radius-16` | `16px` | 히어로 카드, 주요 패널 |
| `radius-20` | `20px` | 대형 쉘, 에디터, 뷰어 외곽 |

### 4.3 그림자 사용 기준

- `--shadow-sm`: 버튼, 칩, 선택된 탭
- `--shadow-md`: 기본 메인 카드, 우측 보조 패널
- `--shadow-lg`: 랜딩 히어로, AI 노트 전체 쉘, 에디터 전체 쉘 (앱 내부 일반 카드에 사용 금지)

### 4.4 보더 규칙

- 메인 카드 기본 보더: `1px solid var(--border-default)`
- 구분선: `1px solid var(--border-soft)`
- 선택 상태: `2px` 보더 사용 가능
- 모든 섹션에 보더를 두를 필요는 없다

## 5. 레이아웃 분류 체계

### 5.1 4종 레이아웃 유형

| 유형 | 해당 페이지 | 특징 |
|---|---|---|
| 일반 정보형 | Home, Report, MemoryNotes, StudyCalendar, TelegramHub, ExamForge, AdminConsole | PageIntro + 메인 컬럼 + 오른쪽 aside |
| 폼/설정형 | CourseDetail, TutorCustomize, Pricing, Settings, MyHomework | 상단 PageIntro + 메인 입력/선택 + 우측 요약/설명 |
| 작업 공간형 | StudentLearning, AINoteViewer, LessonEditor | 메인 캔버스 최우선, 보조 패널은 조용하게 |
| 마케팅/진입형 | Landing, Auth, Onboarding | 첫 화면 장면 최우선, hero full bleed 허용 |

### 5.2 브레이크포인트

| 구간 | 폭 |
|---|---|
| Desktop XL | 1440px 이상 |
| Desktop | 1280px ~ 1439px |
| Tablet | 1024px ~ 1279px |
| Mobile | 768px ~ 1023px |
| Small Mobile | 767px 이하 |

### 5.3 페이지 폭·여백 규칙

- 일반 정보형 최대 폭: `var(--page-max-w)` 유지
- 폼/설정형 최대 폭: `1180px ~ 1240px`
- 작업 공간형 최대 폭: `var(--page-max-w)` 유지
- 마케팅/진입형: 섹션별 자유, hero는 full bleed 허용
- 좌우 패딩: `var(--page-px)`
- 상단 패딩: `var(--page-py)`
- 하단 패딩: `48px`
- 섹션 간 기본 간격: `var(--section-gap)`

### 5.4 반응형 배치 규칙 (일반 정보형 기준)

- 1280px 이상: main + aside 2열
- 1024px ~ 1279px: main + aside 2열 유지, aside 폭 260px으로 축소
- 1023px 이하: aside를 main 아래로 스택
- 767px 이하: 페이지 padding 축소, 헤더 액션 1개만 유지

## 6. 글로벌 사이드바 규칙

- 폭: 항상 `260px`
- 아이콘 크기: `16px`
- 메뉴 라벨: `12px ~ 13px`
- 활성 메뉴 강조: 배경 1개 + 좌측 강조선 또는 아이콘 색 정도로 끝낸다 (메뉴마다 다른 색 금지)
- 배지, 설명문, 작은 보조 텍스트를 메뉴 행마다 붙이지 않는다
- 그룹 구조: 학습 / 도구 / 관리 (이 3개 그룹만 허용)
- 활성 상태: 배경 `var(--accent-soft)`, 텍스트/아이콘 `var(--accent-primary)`, 좌측 인디케이터 `2px` (활성 메뉴에 그림자 금지)

## 7. 컨텍스트(토글) 사이드바 규칙

### 7.1 기본 규칙

- 폭: `260px` (글로벌과 동일)
- 기능 항목 수: 최대 5개
- 설명이 없는 항목을 기본으로 한다. 설명이 필요해도 1줄로 제한한다

### 7.2 피처 아이템 크기

- 한 행 높이: `40px ~ 44px`
- 아이콘 크기: `14px`
- 라벨 크기: `12px`
- count 배지는 우측 끝에 작게만 둔다
- hover 시 배경만 약하게 변경 (확대 효과 금지)

### 7.3 기능 이름 작성 기준

- 명사 나열이 아니라 행동 중심 문장으로 작성한다
- 좋은 예: "이어서 학습", "오늘 복습", "이번 주 요약", "코인 패키지 보기"
- 나쁜 예: "슬라이드 패널", "차트", "리포트", "과제 탭"

| route | 항목 |

## 9. 공통 UI 프리미티브

공통 컴포넌트는 `src/components/ui/` 폴더에만 둔다. 도메인 폴더마다 비슷한 버튼/배지/카드를 새로 만들지 않는다.

### 9.1 PageIntro (`src/components/ui/PageIntro.tsx`)

- 역할: 페이지 헤더 통일 (eyebrow + 제목 + 설명 + 우측 액션)
- props: `eyebrow`, `title`, `description?`, `actions?`, `compact?`
- 규칙: 액션 버튼은 기본 1개, 최대 2개. 제목만 크고 설명은 짧아야 한다

### 9.2 SectionFrame (`src/components/ui/SectionFrame.tsx`)

- 역할: 반복되는 섹션 쉘 통일
- props: `title?`, `description?`, `action?`, `children`, `padded?`, `tone?: 'default' | 'subtle' | 'transparent'`
- 규칙: 내용이 레이아웃 그 자체인 경우만 `tone='transparent'`. 설명은 1문장을 넘기지 않는다

### 9.3 MetricTile (`src/components/ui/MetricTile.tsx`)

- 역할: KPI·성과 수치·잔액 카드 공통
- props: `label`, `value`, `meta?`, `tone?: 'neutral' | 'accent' | 'danger' | 'warning'`
- 규칙: 첫 화면 KPI는 최대 3개. delta·설명·보조 통계를 한 카드에 모두 넣지 않는다

### 9.4 StatusBadge (`src/components/ui/StatusBadge.tsx`)

- 역할: 상태 배지 통일
- props: `tone: 'success' | 'warning' | 'danger' | 'neutral' | 'info'`, `label`, `size?: 'sm' | 'md'`
- 규칙: 상태 표현에 이모지 사용 금지. 코스·과제·결제·텔레그램 상태를 이 컴포넌트로 통일

### 9.5 SegmentedControl (`src/components/ui/SegmentedControl.tsx`)

- 역할: 상단 탭, 필터 탭, 범위 전환 공통화
- props: `items: { id: string; label: ReactNode; icon?: ReactNode }[]`, `value`, `onChange`, `compact?`
- 주요 사용처: PricingTabs, ReportHeader, LearningRightPanel, AINoteViewer 우측 탭

### 9.6 InspectorPanel (`src/components/ui/InspectorPanel.tsx`)

- 역할: 오른쪽 보조 패널 통일
- props: `title?`, `children`, `sticky?`
- 규칙: 보조 패널은 메인 카드보다 배경이 더 조용해야 한다. 메인 카드보다 보더/그림자가 강하면 안 된다

## 10. 모션 시스템

### 10.1 DURATION 값 (`src/shared/motion/transitions.ts`)

```ts
export const DURATION = {
  fast:  0.16,
  base:  0.22,
  panel: 0.28,
  slow:  0.42,
} as const;
```

### 10.2 EASING 값

```ts
export const EASING = {
  easeOut: [0.22, 1, 0.36, 1],
  easeIn:  [0.32, 0, 0.67, 0],
  spring:  [0.16, 1, 0.3,  1],
} as const;
```

### 10.3 사용 기준

- hover, 버튼 반응: `fast`
- 카드/섹션 등장, 탭 전환: `base`
- 패널 열림/닫힘: `panel`
- 페이지 레벨 등장, 큰 전환: `slow`

### 10.4 variant 정의 (`src/shared/motion/variants.ts`)

| variant | hidden | visible |
|---|---|---|
| `fadeIn` | `opacity: 0` | `opacity: 1` |
| `slideUp` | `opacity: 0, y: 10` | `opacity: 1, y: 0` |
| `slideDown` | `opacity: 0, y: -10` | `opacity: 1, y: 0` |
| `slideLeft` | `opacity: 0, x: 20` | `opacity: 1, x: 0` |
| `slideRight` | `opacity: 0, x: -20` | `opacity: 1, x: 0` |
| `scaleIn` | `opacity: 0, scale: 0.985` | `opacity: 1, scale: 1` |
| `staggerContainer` | — | `staggerChildren: 0.05`, `delayChildren: 0.04` |

### 10.5 전역 금지 규칙

- 페이지의 모든 카드에 reveal 넣기
- hover마다 scale `1.03` 이상 사용
- modal이 아닌데 scaleIn 남발
- `bounce`, `elastic`, `spring` 과장 사용
- 모바일에서 300ms를 넘는 긴 모션
- 장식용 모션 (있는 이유가 없으면 제거)
- motion 수치를 각 컴포넌트에서 하드코딩 (반드시 공통 파일 참조)

## 11. 접근성 필수 규칙

- 일반 텍스트 대비: **4.5:1** 이상
- 큰 텍스트 대비: **3:1** 이상
- keyboard focus ring 유지 (버튼, 탭, 입력창, 리스트 행 전부). focus 색은 `--accent-primary` 계열
- 버튼 최소 높이: **40px** (모바일 주요 액션은 **44px** 권장)
- `prefers-reduced-motion` 환경에서는 entrance motion, stagger, parallax를 약화하거나 제거한다
- 색만으로 상태를 전달하지 않는다. 상태는 텍스트 또는 배지 라벨을 함께 제공한다

## 12. 이모지 사용 규칙

- UI 라벨, 버튼, 탭, 배지에 이모지 사용 금지
- 아이콘이 필요하면 `Icon` 컴포넌트 또는 SVG 아이콘으로 교체한다
- 텍스트만으로 충분하면 아이콘도 제거한다
- 텍스트 화살표 `→`도 버튼 라벨에서 제거한다

## 14. 애니메이션 UI 컴포넌트

`src/components/animated/`에 위치하며 `index.ts`로 배럴 익스포트된다.

공통 전제 조건:
- 모든 컴포넌트는 `motion/react`를 사용한다. `framer-motion` 직접 임포트 금지다.
- 모든 컴포넌트는 `useReducedMotion` 훅으로 `prefers-reduced-motion`을 지원한다.
- duration·easing 값은 `@/shared/motion/transitions`에서 임포트한다. 컴포넌트 안에서 하드코딩 금지다.

### 14.1 컴포넌트 목록

| 컴포넌트 | 역할 | 주요 props | 적용 페이지 |
|---|---|---|---|
| `AuroraBackground` | 히어로 배경 블롭 3개 자동 부유 | `palette`, `active?` | Landing |
| `SpotlightCard` | 커서 따라가는 radial gradient 카드 래퍼 | `radius?`, `opacity?`, `color?` | Landing, MyCourses, Pricing |
| `TextReveal` | 단어별 순차 등장 (stagger) | `text`, `tag?`, `staggerDelay?` | Landing |
| `NumberCounter` | 숫자 카운팅 애니메이션 | `to`, `format?`, `duration?` | Home, Report, Pricing |
| `GlowBorder` | 숨 쉬는 보더 glow 이펙트 | `color?`, `intensity?`, `duration?` | Home (ContinueCard 1곳만) |
| `ShimmerButton` | 호버 시 대각선 빛줄기 CTA 버튼 | `shimmerColor?` | Landing, ExamForge, CourseDetail |
| `ProgressRing` | SVG 원형 프로그레스 | `progress`, `size?`, `strokeWidth?`, `label?` | Sidebar, Calendar |

### 14.2 사용 규칙

1. Landing 제외 페이지에서 동시에 2종 이상 애니메이션이 눈에 들어오면 과한 것이다.
2. 같은 효과가 화면에 3개 이상 보이면 과한 것이다.
3. 학습 콘텐츠(StudentLearning, AINoteViewer) 위에 장식 애니메이션은 금지한다.
4. 애니메이션 없이도 기능이 이해되어야 한다 — 보강 수단이지 필수가 아니다.
5. `GlowBorder`는 Home "이어서 학습" 카드 1곳만 허용하며, 2곳 이상 사용은 금지한다.

### 14.3 페이지 유형별 적용 강도

| 페이지 유형 | 적용 종수 | 강도 |
|---|---|---|
| 마케팅 (Landing) | 4종 | HIGH |
| 대시보드 (Home) | 2종 | MEDIUM |
| 목록형 (MyCourses, Pricing) | 1~2종 | LOW |
| 작업형 (Learning, AINoteViewer) | 0종 | NONE |
| 설정형 (Settings, Tutor) | 0종 | NONE |

### 14.4 PageContextFeatureType 확장

`PageContextFeatureType`은 기존 `'anchor' | 'filter' | 'subview'`에 `'modal'` 타입이 추가된다.

- `modal` 타입은 `AppState.activeModal` 키를 활성화해 Sheet/Dialog 모달을 여는 데 사용한다.
- 컨텍스트 사이드바 피처 항목에서 모달을 여는 경우 이 타입을 지정한다.
