> 작성일: 2026-04-20 | 최종 수정: 2026-05-25 (최종 기능 범위 반영) | 대상: 멘토 검토용 | 기준 문서 버전: 페이지별_기능정리.md v1.6, API 명세서 v2.8.0, ERD

## 1. 서비스 한 줄 소개

일과(ilkwa)는 PDF나 주제 텍스트를 넣으면 AI가 커리큘럼부터 음성 강의·과제·채점까지 1:1 과외 과정을 만들어 주는 학습 플랫폼이다.

---

## 2. 핵심 가치

- 자료가 없어도 시작할 수 있다. 주제만 넣으면 AI가 커리큘럼을 설계한다. PDF 업로드와 주제 입력 두 진입점을 똑같이 지원한다.
- 1:1 과외 경험. 학생이 고른 AI 선생님 캐릭터가 학생 이력에 맞춰 답한다. 관찰당하는 느낌 없이 둘이 공부하는 환경을 목표로 했다.
- 학습이 끊기지 않는다. 텔레그램 봇으로 과제를 내고 채점 결과를 DM으로 받는다. 앱을 열지 않아도 학습이 이어진다.

## 4. 두 가지 입력 모드

### (A) PDF 업로드 모드

교재나 강의자료가 있는 사람이 쓴다. PDF를 올리면 AI가 문서를 분석해 챕터·슬라이드 구조를 만든다.

- 파일 크기 제한: 1.5GB (PDF 기준)
- 처리 경로: `POST /tutoring` (type: "pdf") → Spring 권한·상태 생성 → FastAPI `CourseCreationAgent` → 커리큘럼 초안 DB 저장 → 사용자 확인
- 참고도서 OCR: OCR_V1 파이프라인으로 처리한다. Marker 1차 추출 → 품질 게이트 → 걸린 페이지만 MinerU 재추출 + Kanana-2 교정 → BGE-M3 Dense+Sparse 임베딩 → RRF + BGE-Reranker → Qdrant `ocr_v1_chunks` 색인

#### OCR_V1 처리 경로 (2026-05-21부터 ①b 파이프라인 대체)

교재를 포함한 모든 PDF는 OCR_V1로 처리한다. 기존 ①b(PaddleOCR-VL-1.5 Modal A10) 파이프라인을 대체했고 `POST /ocr_v1/ingest`(port 8005)로 들어온다.

- 처리 방식: Marker 1차 추출 → 품질 게이트(4-메트릭 자동 평가) → MinerU 폴백 재추출 + Kanana-2 교정 → BGE-M3 Dense+Sparse 임베딩 → Qdrant `ocr_v1_chunks` 색인
- 품질 게이트 자동 폴백: 임계값에 못 미친 페이지만 MinerU로 다시 추출하고 Kanana-2로 교정한다. 전 페이지에 Kanana-2를 적용하면 원문에 없는 문장이 붙어 CER이 0.437로 오르므로 게이트에 걸린 페이지로 한정했다.
- 측정: 교재 테스트셋 30쪽(텍스트 22 · 스캔 8)에서 최종 CER 0.003(스캔 페이지 0.009).
- 검색: Dense + Sparse 병렬 검색 → RRF(k=60) 통합 → BGE-Reranker-v2-m3 재정렬

### (B) 주제 입력 모드

교재가 없어도 학습 주제(예: "미분적분학 기초", "자료구조 그래프 탐색")를 텍스트로 넣으면 AI가 커리큘럼 전체를 설계한다.

- 입력: 최대 2,000자 자유 텍스트
- 처리 경로: `POST /tutoring` (type: "topic") → Spring 권한·상태 생성 → FastAPI `CurriculumPlanner(Opus)` → 커리큘럼 초안 DB 저장 → 사용자 확인

### 두 모드의 합류 지점

진입점과 관계없이 커리큘럼 확정 이후 흐름은 같다.

```
커리큘럼 확정
    ↓
강의 1개 단위 생성 파이프라인 (롤포워드 병렬)
    ↓
슬라이드 iframeHtml 생성 · TTS 음성 합성 · 이해도 퀴즈 생성
    ↓
과외 뷰어에서 강의 진행
    ↓
과제 생성 · 발송 · 채점
```

## 7. AI 파이프라인 요약

### 커리큘럼 생성 (파이프라인 ④)

커리큘럼 생성과 강의 생성을 나눈다. `Planner(Opus)`는 1강당 1회 (커리큘럼 설계) 호출돼 강의 슬롯마다 계획을 채우고, 10~15개 강의 계획을 DB에 저장한다. 사용자가 커리큘럼을 확정하면 Spring이 생성 입력 스냅샷을 `lesson_generation_status.generation_context`에 저장하고, ChapterStudio_V1은 `lesson_id`로 DB에서 해당 스냅샷을 읽어 강의 1개 단위로 슬라이드 10~15장, 퀴즈, 핵심노트, 과제, 음성대본을 병렬 생성한다. 학생이 N번째 강의를 완료하면 N+2 강의 생성이 백그라운드에서 시작된다. Checkpointer로 상태를 남겨 중단 후 재개할 수 있다.

### 슬라이드 + TTS 음성 합성

슬라이드는 ChapterStudio_V1이 템플릿 75종(JSON) 중 하나를 골라 빈칸을 채우고, HTML/CSS 렌더, Shiki/Mermaid/KaTeX/차트 후처리, sanitize, 프론트 삽입용 문서 조립을 끝낸 `iframe_html`로 저장한다. 이 값은 iframe 태그가 아니라 빈 학습 프레임의 `iframe srcDoc`에 넣을 완성 HTML 문서다. 프론트엔드는 앱 DOM에 raw HTML을 삽입하지 않고 `sandbox="allow-scripts"` iframe으로만 렌더링한다. 슬라이드별 TTS를 Qwen3-TTS(Modal H100)로 문장 단위 합성한 뒤 ffmpeg로 이어 붙이고, Cue Point 타임스탬프를 `slide` 테이블에 저장한다. 재생 시 프론트엔드는 Cue Point를 신뢰해 슬라이드 전환을 처리한다. 현재 재생 위치는 클라이언트 런타임 상태로만 관리한다.

실전 검증 보고서는 [메인강의생성_실전검증.md](../05_실측/메인강의생성_실전검증.md)에 있다. 최신 보고서에는 15슬라이드 강의, 슬라이드별 과외식 음성대본, 핵심노트, 퀴즈, 과제, 참고도서/약점 반영 여부가 포함된다. 최종 구성 전에 돌린 2026-05-14 Modal B200 검증은 Qwen3.6-27B-FP8 실모델 기준 100점 PASS이며, 음성대본 품질 미달 시 `문단별 생성 -> 병합 -> 품질 gate` fallback을 사용한다. 이 검증 시점에는 Qwen3-TTS Modal 엔드포인트를 설정하지 않아 음성 파일 합성은 빼고 돌렸다. 최종 구성에서 1강(10~15슬라이드) 생성은 준비·생성·검증·음성 포함 120초다(초기 512초, -76.6%).

### 소크라테스 Q&A (파이프라인 ②c)

텍스트 질문 또는 이해도 퀴즈 응답을 받으면 Chat_V1이 Claude Sonnet으로 답한다. `POST /api/chat/v1/ask`는 JSON으로 한 번에, `POST /api/chat/v1/ask/stream`은 SSE로 토큰을 흘려보낸다. 다른 AI 파이프라인은 SSE를 쓰지 않는다. 근접·오답·부분이해로 판정되면 `WeakConceptLinker(Haiku)`가 `weakness_profile`을 갱신한다.

### 강의 맞춤 채팅

학습 화면 채팅은 일반 Q&A와 분리한다. 프론트는 `tutoringId`, `lessonId`, `slideId`, `slideIdx`, 질문, 선택 문장, 재생 위치만 전달한다. ChapterStudio_V1은 DB에서 현재 슬라이드, 음성대본, 핵심노트, 강의 끝 퀴즈, 튜터 설정, 사용자 취약점을 읽어 과외식 답변을 만든다. 운영 모델은 FastAPI connector 설정으로 정한다.

### 암기노트 (슬라이드 단위)

챕터 생성 시 슬라이드별 핵심 요약 노트(`memo_note`)가 자동 생성된다. 슬라이드 ID로 참조하며, 텔레그램으로 발송하거나 웹 PAGE 17에서 과목 단위로 모아 열람할 수 있다.

### Self-Healing Memory (SHM, 미구현 설계안)

LLM 튜터의 context entropy 문제를 풀려고 설계한 3계층 메모리다. 구현하지 않았다. L2 포인터(~150자/라인)를 항상 컨텍스트에 올리고, L3 도메인 파일(취약 개념·풀이 이력 등)은 S3/MinIO에서 필요할 때 읽는다. 에이전트가 레이어를 스스로 다시 쓴다. `Daily Consolidation(Celery 자정 Beat)`이 하루치 학습 이벤트를 요약해 SHM을 갱신한다.

### OCR_V1 파이프라인 (2026-04-23 추가, 2026-05-21 갱신)

LangGraph 8-Stage StateGraph 기반 모듈식 OCR 파이프라인이다. 기존 ①b PaddleOCR-VL-1.5 Modal 파이프라인을 대체해 교재를 포함한 모든 PDF를 한 경로로 처리한다.

| 항목 | OCR_V1 (현재 단일 경로) |
|---|---|
| 대상 문서 | 교재 포함 모든 PDF 문서 |
| OCR 엔진 | Marker 1차 + MinerU 자동 폴백 (이중 엔진) |
| 품질 보증 | 4-메트릭 품질 게이트 자동 평가·폴백, 걸린 페이지만 Kanana-2 교정 |
| 임베딩 방식 | BGE-M3 dense(1024d) + sparse |
| 검색 방식 | Dense+Sparse → RRF(k=60) → BGE-Reranker |
| 색인 컬렉션 | `ocr_v1_chunks` |
| 진입점 | `POST /ocr_v1/ingest` (port 8005) |

파이프라인 상세: [AI_파이프라인_설계.md](../01_아키텍처/AI_파이프라인_설계.md)

### 강의-슬라이드 구조 제약

AI는 커리큘럼을 만들 때 강의당 슬라이드를 10~15개로 맞춘다. Free 플랜은 롤링 언락 방식이다. 10~15개를 모두 만들되 항상 2개만 활성 상태로 둔다. 1개 완료 시 다음 1개가 자동 해제된다. 이 규칙은 PDF 기반·주제 입력 모드 모두 적용된다.

| 기능 | 설명 |
|------|------|
| 과제 전달 | 생성된 과제를 텔레그램 DM으로 발송 |
| 암기노트 전달 | 슬라이드별 암기노트 텔레그램 발송 |
| 과제 제출 | 학생 → 텔레그램 → 서버 파일 제출 |
| AI 채점 | 제출물 자동 채점 후 결과 DM 회신 |

| 플랜 | 허용 범위 |

| Free | `is_default=true` 기본 튜터 2종(선생님형·누나형) 선택만 가능. T1·T3 read-only |
