## AI 파이프라인 설계 원칙

FastAPI가 모든 AI 진입점을 맡는다. LangGraph 에이전트 프레임워크를 FastAPI에 확장하는 구조다. SSE는 FastAPI AI 파이프라인 전역 금지다. 완료 통지는 polling 또는 다음 요청 piggyback 방식을 사용한다. 예외는 Chat_V1 `POST /api/chat/v1/ask/stream` 하나로, 채팅 답변을 SSE로 흘려보낸다. Spring Boot도 강의·알림 SseEmitter를 구현하지 않는다. 모든 PDF OCR은 OCR_V1(Marker + MinerU 이중 엔진 + BGE-M3 Dense+Sparse + Qdrant) 단일 경로로 처리한다. ~~②c 소크라테스 스트리밍~~ 및 `ilkwa_rust_ext` PyO3 + PaddleOCR ONNX 경로는 폐기됐다.

### 페이지 목적
서비스의 첫 인상을 결정하는 마케팅 페이지. 방문자에게 일과의 핵심 가치를 전달하고 회원가입으로 전환시키는 것이 목표이다.

### 기능 목록

| # | 기능명 | 설명 | 구분 |
|---|--------|------|------|
| 1 | 히어로 섹션 | 서비스 소개 메인 영역. 태그라인: "AI가 만드는 나만의 1:1 과외 선생님" | 필수 |
| 2 | 핵심 기능 요약 카드 | 3가지 핵심 기능을 카드 형태로 시각화 | 필수 |
| 3 | 요금제 비교표 | Free(무료) vs Pro(월 14,900원) vs Premium(월 49,900원) 3종 기능 비교 | 필수 |
| 4 | 서비스 시연 데모 | 실제 학습 과정을 미리 확인할 수 있는 인터랙티브 데모 | 필수 |

## PAGE 2: 로그인

### 페이지 목적
사용자 인증 및 초기 프로필 설정. 구글/카카오 소셜 로그인으로 진입 장벽을 낮추고, 온보딩을 통해 맞춤 학습 환경을 즉시 구성한다. 자체 이메일/비밀번호 인증과 별도 회원가입 절차는 없다. 소셜 최초 로그인 시 계정이 자동 생성된다.

### 기능 목록

| # | 기능명 | 설명 | 구분 |
|---|--------|------|------|
| 1 | 구글 로그인 | Google OAuth 2.0 기반 원클릭 로그인. 첫 로그인 시 자동 계정 생성 | 필수 |
| 2 | 카카오 로그인 | Kakao OAuth 2.0 기반 원클릭 로그인. 첫 로그인 시 자동 계정 생성 | 필수 |
| 3 | 약관 동의 | 서비스 이용약관(필수), 개인정보 처리방침(필수), 마케팅 수신(선택) — 신규 가입 시 온보딩 스텝 1단계로 인라인 표시. 별도 약관 페이지/모달 없음 | 필수 |
| 4 | 닉네임 설정 | 소셜 프로필에서 자동 수집된 닉네임 확인·수정 (온보딩 스텝 2단계) | 필수 |
| 5 | 1차 온보딩 | 관심 추천 강의 선택 (온보딩 스텝 3단계) | 필수 |
| 6 | 기본 AI 튜터 선택 | 기본 제공 튜터 2종(선생님형·누나형) 중 선택 (온보딩 스텝 4단계). 상세 커스터마이징은 PAGE 18에서 수행 | 필수 |
| 7 | 튜터 미리보기 | 선택한 AI 튜터의 대화 예시 + 프로필 확인 | 필수 |
| 8 | 텔레그램 연동 | t.me/ilgwa_EZ_Team_bot?start={token} 링크 + QR코드 제공 | 선택 |

PAGE 3 (대시보드) 이동
```

## PAGE 5: 과외 뷰어

### 페이지 목적
실제 AI 과외가 진행되는 핵심 학습 화면. 슬라이드와 음성을 동기화하여 강의를 제공하며, 소크라테스식 질의응답과 인터랙티브 Q&A를 통해 능동적 학습을 유도한다.

### 기능 목록

| # | 기능명 | 설명 | 구분 |
|---|--------|------|------|
| 1 | 슬라이드 + 음성 동기화 재생 | 슬라이드 전환과 AI 음성 설명의 실시간 동기화 | 필수 |
| 2 | 스마트 스케줄링 | 사전 생성 + 버퍼링 + SSE로 끊김 없는 재생 | 필수 |
| 3 | 이전 과제 해설 도입부 | 강의 시작 시 이전 과제 결과 해설 + 피드백 제공 | 필수 |
| 4 | 소크라테스 모드 | 실시간 소크라테스 대화 (②c, SSE 스트리밍) — AI가 질문 → 사용자 답변 → 근접·정답·포기 표명 시 정답 공개, 그 전까지 공개 금지. 오답/부분이해 시 WeakConceptLinker 호출 | Premium |
| 5 | 인터랙티브 Q&A | 마이크 입력 → ASR(음성인식) → RAG 검색 → TTS 음성 응답 | 필수 |
| 6 | 이해도 체크 | 3~5 슬라이드마다 이해도 확인 퀴즈 삽입 (②c 소크라테스 대화 방식). 정답 즉시 공개 금지 — 근접·정답·포기 표명 시 공개. 오답/부분이해 시 WeakConceptLinker 호출, 부족 시 보충 설명 | 필수 |
| 7 | 적응형 난이도 | 학습자 수준에 따라 실시간 난이도 자동 조절 | Premium |
| 8 | 멀티뷰 | 슬라이드 + 노트 + 풀이과정 등 다중 패널 동시 표시 | Premium |
| 9 | 북마크 | 중요 슬라이드에 북마크 설정 → 나중에 빠르게 이동 | 필수 |
| 10 | 재생 컨트롤 | 재생/정지, 속도 조절(0.5x~2.0x), 슬라이드 점프 | 필수 |
| 11 | AI 노트 | AI가 핵심 내용 자동 생성 + 사용자 메모 + 별표 기능 | 필수 |
| 12 | 캐릭터 말투 설명 | 선택한 AI 선생님 캐릭터의 말투로 모든 설명 제공 | 필수 |
| 13 | 풀이 과정 추적 UI | Step-by-Step 풀이 과정을 시각적으로 표시 | 필수 |

### 사용자 흐름
```

## PAGE 6: 과제

### 페이지 목적
과외 완료 후 자동 생성되는 과제를 풀고, AI가 자동 채점 및 피드백을 제공하는 학습 강화 페이지. 약점을 분석하여 반복 학습을 유도한다.

### 기능 목록

| # | 기능명 | 설명 | 구분 |
|---|--------|------|------|
| 1 | 자동 과제 생성 | 과외 완료 시 가용 시간 기반 자동 생성 — 3축 가중치(질문빈도·되감기·오답률)로 출제 파트 선별 | 필수 |
| 2 | 가용 시간 기반 유형 결정 | 10분=객관식, 30분=혼합, 1시간+=서술형 | 필수 |
| 3 | 풀이 과정 추적 | Step-by-Step Trace로 풀이 과정 기록 (Opus) | Premium |
| 4 | 오류 패턴 분류 | 계산 오류 / 개념 오류 / 공식 오류 / 해석 오류로 자동 분류 | 필수 |
| 5 | 텔레그램 자동 전달 | 과제를 텔레그램 봇으로 자동 전송 | 필수 |
| 6 | 텔레그램 제출 | 사진/PDF로 답안 촬영하여 텔레그램으로 제출 | 필수 |
| 7 | 웹 파일 제출 | 인앱에서 직접 파일 업로드로 과제 제출 — 허용 확장자 화이트리스트 적용 | 필수 |
| 8 | AI 자동 채점 | 텔레그램 비동기 채점 (⑥) — 텔레그램 DM으로 파일 첨부 제출 → AssignmentGrader가 파일 타입 판단 후 처리(이미지/PDF→①a (Sonnet 4.6 VLM 직접 처리, OCR 레이어 없음)→plain_text, .py→AST파싱, .txt/.md→자유서술, .zip→해제 후 분기, 음성→ASR→텍스트) → 채점 → 해설 → 텔레그램 DM 회신. 문제 설계는 3축(핵심+실무+약점) 기반 | 필수 |
| 9 | 채점 결과 조회 | 채점 상태 4단계(queued → grading → done/failed) 실시간 확인 | 필수 |
| 10 | 재제출 | queued/grading 구간에서만 최신 파일로 덮어쓰기 허용 — done/failed 이후 버튼 비활성화 | 필수 |
| 11 | 마감일 표시 | assignment.due_date 기준 마감 시각 표시 — 24h 이내 임박 배지 강조 | 필수 |
| 12 | 피드백 생성 | 문제별 상세 피드백 + 개선 방향 제시 | 필수 |
| 13 | 약점 리포트 | 오류 패턴 기반 약점 분석 리포트 | 필수 |
| 14 | Self-Healing Memory 연동 | 틀린 문제를 기억하고 반복 출제 | 필수 |
| 15 | 암기노트 생성 | 슬라이드별 암기노트 생성 → 텔레그램 전송 + 웹 주제별 모음 페이지 저장 | 필수 |

### 오류 패턴 분류 체계

| 오류 유형 | 설명 | 예시 |
|----------|------|------|
| 계산 오류 | 풀이 과정은 맞으나 계산 실수 | 3+7=11로 잘못 계산 |

| 해석 오류 | 문제를 잘못 해석 | 문제 조건을 누락하여 잘못된 방향으로 풀이 |

### 출제 가중치 로직

과제 문항의 출제 파트는 학습 중 축적된 3가지 시그널을 결합해 결정한다.
"어려운 문제를 몇 개 낼지"는 기존 `difficultyDistribution`이 그대로 맡고,
"어느 파트에서 낼지"만 가중치가 결정한다.

#### 가중치 공식

```
score(slide) = α × 질문밀도 + β × 되감기_비율 + γ × 오답률
```

| 시그널 | 변수 | 초기값 | 측정 방법 |
|--------|------|--------|-----------|
| 질문밀도 | α | 0.4 | 해당 슬라이드 QA COUNT |
| 되감기 비율 | β | 0.3 | seek + `payload.direction=back` / play 이벤트 수 |
| 오답률 | γ | 0.3 | 해당 개념 누적 오답 / 총 출제 수 |

- 3축 시그널 각각 0~1로 정규화 후 가중합 산출
- 상위 N개 슬라이드/개념을 출제 후보로 선별 (N = `questionCount` 기준 자동 결정)
- 질문이 없는 슬라이드는 α 기여분이 0 → 자연 탈락
- α / β / γ는 관리자 API(`weightOverride`)로 실시간 튜닝 가능

#### UX 메시지 예시

> "이번 과제는 네가 자주 질문한 파트 위주로 구성했어"

### 파일 업로드 제약

웹 인앱 제출 시 다음 규칙을 적용한다.

#### 과제 기대 형식 (L2 — 과제 생성 시 지정)

과제를 생성할 때 교사(또는 Qwen3 자동 생성)가 아래 2개 필드를 반드시 지정한다. 지정된 값은 `assignment` 테이블에 저장되고, 제출 시 L2 검증에 참조된다.

| 필드 | 타입 | 설명 |
|------|------|------|
| `expected_input_type` | Enum | 과제 유형 단일 선택. 후보: `code_python` / `text_essay` / `handwritten_solution` / `audio_oral` / `project_archive` |
| `allowed_extensions` | 문자열 배열 | `expected_input_type`에서 자동 파생. 교사가 override 가능 |

##### `expected_input_type` 기본 확장자 대응표

| 유형 | 기본 `allowed_extensions` |
|------|--------------------------|
| `code_python` | `[".py"]` |
| `text_essay` | `[".txt", ".md"]` |
| `handwritten_solution` | `[".png", ".jpg", ".jpeg", ".pdf"]` |
| `audio_oral` | `[".mp3", ".m4a", ".wav"]` |
| `project_archive` | `[".zip"]` |

> 과제 생성 UX: 교사가 유형을 선택하면 `allowed_extensions`가 자동 제안된다. 필요 시 교사가 직접 override할 수 있다.

#### 제출 검증 3-레이어

| 레이어 | 검증 내용 |
|--------|----------|
| L1 | 확장자 화이트리스트 체크 — `assignment.allowed_extensions` 참조 |
| L2 | `expected_input_type` vs 실제 파일 유형 일치 확인. 불일치 시 즉시 거절. 거절 사유 `REJECTED_TYPE_MISMATCH` 반환 |
| L3 | 내용 검증 — 빈 파일, 용량 초과, zip bomb 등 |

거절 시 AI가 `rejection_reason` 파라미터를 받아 사용자 친화 메시지를 생성한다. 메시지 어투는 내부 정책에 따른다.

#### 전체 허용 확장자 (L1 글로벌 화이트리스트)

| 구분 | 허용 확장자 |
|------|------------|
| 압축 파일 | `.zip` |
| 문서 | `.pdf` |
| 이미지 | `.png`, `.jpg` / `.jpeg`, `.webp` |
| 코드 | `.py` |
| 텍스트 | `.txt`, `.md` |
| 음성 | `.mp3`, `.m4a`, `.wav` |

> L1 화이트리스트를 통과하더라도 L2에서 과제의 `expected_input_type`과 맞지 않으면 거절된다. 예: `handwritten_solution` 과제에 `.py` 파일 제출 시 L2 거절.

zip 내부 허용 확장자: `.pdf`, `.png`, `.jpg` / `.jpeg`, `.webp`

##### zip 제약

| 항목 | 제한값 |
|------|--------|
| 내부 파일 수 | 최대 30개 |
| 압축 해제 총 용량 | 최대 100MB |
| 압축률 | 100:1 초과 시 업로드 차단 (zip bomb 방어) |

업로드 파일 크기 제한: 20MB (단일 파일 기준)

### 채점 결과 대기 / 조회

#### 채점 안내 (텔레그램 비동기)

과제 채점은 배치 처리가 아닌 텔레그램 비동기 방식(⑥)으로 진행한다. 텔레그램 봇에 파일을 DM으로 첨부 제출하면 AssignmentGrader가 파일 타입을 판단해 처리 분기(이미지/PDF→①a OCR, .py→AST파싱, .txt/.md→자유서술, .zip→해제 후 분기, 음성→Whisper V3 Turbo ASR)한 뒤 채점하고, 결과를 텔레그램 DM으로 회신한다. 마감일(`due_date`) 이전 제출만 공식 점수에 반영된다.

> Daily 배치 채점(06:00·12:00·18:00·24:00)은 폐지됨. Daily Consolidation(매일 자정)은 채점이 아닌 하루 학습 요약 전용이다.

#### 제출 상태 4단계

| 상태 | 학생용 라벨 | 색상 힌트 |
|------|------------|----------|
| `queued` | 텔레그램 채점 큐 등록됨 | 연파랑 |
| `grading` | 채점 진행 중 | 주황 |
| `done` | 채점 완료 | 초록 |
| `failed` | 채점 실패 — 재제출 필요 | 빨강 |

부분 OCR 실패 알림: 일부 페이지가 불명확하게 인식된 경우 결과 화면 상단에 경고 배너를 표시한다.

> "일부 페이지가 불명확하여 채점되지 않았습니다 (n/total)"

### 알림 경로

채점이 완료되면 Spring이 다음 경로로 결과를 전달한다.

| 수신 조건 | 전달 방식 | 내용 |
|----------|----------|------|
| 텔레그램 연동 계정 | AssignmentGrader 채점 완료 직후 DM 회신 | `{점수}/{만점}` + 피드백 링크 |
| 웹 접속 중 | REST polling `/api/notifications/stream` | `grading_completed` 알림 상태 조회 |
| 텔레그램 + 웹 연동 | 두 채널 모두 수신 | 채널 독립 동작, 한 쪽 실패 시 나머지 정상 전달 |

텔레그램으로 제출하더라도 웹 대시보드에서 점수를 조회할 수 있으며, 웹으로 제출하더라도 텔레그램이 연동되어 있으면 텔레그램으로 결과를 수신한다.

## PAGE 16: 슈퍼 관리자 페이지

### 페이지 목적
유저의 텔레그램 연동 상태와 AI 튜터 대화 흔적을 운영자가 직접 조회·교정할 수 있는 내부 운영 도구다. 학생 CS 대응, 데이터 오류 복구, 악성 이용 모니터링을 위한 관리 화면이다.

### 접근 권한
- 슈퍼 관리자 역할(`role = SUPER_ADMIN`)만 접근 가능하다.
- 일반 관리자·튜터·학부모·학생은 이 페이지 자체를 볼 수 없다.

### 기능 목록

| # | 기능명 | 설명 | 구분 |
|---|--------|------|------|
| F16.1 | 텔레그램 chat_id 관리 | 유저 단위 `telegram_account.telegram_chat_id` 직접 편집 + 연동 해제·재연동 | 필수 |
| F16.2 | 채팅내역 조회 | 텔레그램 봇 DM 및 AI 튜터 대화 기록 조회 (조회 전용) | 필수 |
| F16.3 (보안) | 관리자 텔레그램 자격정보 관리 | 운영 봇 토큰·관리자 본인 chat_id 조회·수정 | 필수 |

### F16.1 텔레그램 chat_id 관리

- 유저 단위로 `telegram_account.telegram_chat_id` 값을 **직접 편집**할 수 있다.
- 유저의 텔레그램 연동을 **해제**하거나, 다른 chat_id로 **재연동**할 수 있다.
- 편집 이력은 audit 로그에 남긴다. 세부 audit 스키마는 Spring 담당자가 최종 확정한다.

### F16.2 채팅내역 조회

- **텔레그램 봇 DM 내역**을 chat_id 기준으로 조회할 수 있다 (`telegram_message` 테이블 기반).
- 추가로 웹 AI 튜터 대화, 음성 Q&A 세션, 과제 제출·채점 내역도 같은 유저 화면에서 조회 가능하도록 한다. 상세 조회 범위는 Spring 담당자가 최종 결정한다.
- **조회 전용** 기능이다. 채팅내역 편집·삭제 권한은 이번 단계에서 제공하지 않는다.

### F16.3 관리자 텔레그램 자격정보 관리 (보안)

- **텔레그램 봇 토큰** (서비스 운영에 쓰는 봇의 API 토큰)을 슈퍼 관리자가 조회·수정할 수 있다. 토큰 로테이션 시 재배포 없이 교체 가능하게 한다.
- **관리자 본인 chat_id** (봇이 관리자에게 운영 알림·이상 감지 메시지를 보낼 대상)를 조회·수정할 수 있다. 복수 슈퍼 관리자 계정이면 계정별로 각자의 chat_id를 갖는다.
- 봇 토큰은 DB에 **암호화 저장**하고, 조회 화면에는 마스킹하여 보여준다. 세부 암호화 스키마·rotation 정책은 Spring 담당자가 확정한다.
- 수정 시 감사 로그 (who / when / before·after 해시)를 남긴다.
- 저장 직후 Telegram `getMe` 헬스체크를 자동으로 돌려 토큰 유효성을 확인한다. 실제 호출 담당 컴포넌트는 Spring 담당자가 확정한다.

### 데이터 필드

| 기능 | 원천 테이블 |
|------|------------|
| F16.1 유저 chat_id 편집 | `telegram_account` |
| F16.2 텔레그램 DM 조회 | `telegram_message` |
| F16.2 AI 튜터 대화 조회 | `socratic_session` |
| F16.3 관리자 자격정보 | `admin_telegram_credential` |

### 비고
- 화면 레이아웃·세부 인터랙션·엔드포인트 스펙은 **Spring 담당자가 최종 확정**한다.
- 이번 명세는 "관리자 페이지가 존재하고 텔레그램 chat_id 편집과 채팅내역 관리를 담당한다"는 기능 존재 자체를 못 박는 것이다.

## PAGE 18: AI 튜터 관리

> 2026-04-20 신규: 기존 PAGE 10 AI 선생님 관리를 전면 재설계한 페이지다. 상세 UI는 본 문서 PAGE 18 섹션에 통합됨.

### 페이지 목적

AI 튜터의 성격·말투·설명 방식을 슬라이더로 세밀하게 조정하고, 복수 튜터를 저장·전환하는 전용 관리 페이지다. 라이브 프리뷰로 설정 변경 결과를 즉시 확인할 수 있다.
