문제 상황

원인

토큰 생성 자율도로 인해 16종 디자인 템플릿의 CSS 규칙이 무시되고, 임의 인라인 스크립트 삽입 가능성이 발생했습니다.

고가용성 장애 대응 및 비동기 음성 파이프라인

단일 GPU 장애 시에도 서비스 무중단을 보장하는 Fallback 회로와 비동기 음성 큐를 설계했습니다.

안정성 설계

3단계 비상 대체(폴백) 연결

단일 GPU 다운 시 서비스 중단 방지

단일 클라우드 GPU(Modal B200)에만 의존할 경우 일시적 장애나 할당 지연 시 서비스가 멈추는 문제를 방어했습니다.

엔지니어링 조치

  • 주 경로: Modal GPU (Qwen3.6-27B vLLM)
  • 장애 감지 시 자동 전환: 1차 Gemini 3.5 Flash → 2차 Claude Sonnet 4.5
  • GPU 상태 이상 감지 시 즉각 외부 대체 API로 전환하여 생성 유지

상용 API는 장애 시 사용자에게 에러를 노출하지 않기 위한 비상 우회로로만 제한적으로 사용합니다.

음성 합성

Qwen3-TTS 비동기 큐 워커

아키텍처 분리

  • 연산 부하가 큰 음성 합성을 텍스트 파이프라인에서 분리
  • 슬라이드 대본 완료 즉시 DB 기반 메시지 큐(`voice_script_queue`)로 위임

합성 품질 지표

화자 유사도 0.964~0.976 (기준 ≥ 0.85 달성), Round-trip CER 0.010~0.019 (91~95% 오류 개선), 튀지 않고 일정한 음성 톤 유지.

음성 질의 인식

Qwen3-ASR / mlx-whisper-turbo 기반 실시간 음성 질문 텍스트 변환 (RTF 0.075~0.260).

마이크로서비스 경계

Spring과 FastAPI의 책임 분리

수명주기, 장애 영향도, 대규모 비동기 I/O(`asyncio`)와 의존 라이브러리(PyTorch, vLLM)의 특성이 다른 AI 워크로드를 Spring 메인 스레드로부터 완전히 격리했습니다. 인증·결제·유저 상태 관리는 Spring이 전담합니다.

직접 DB 벌크 INSERT 정책

AI 파이프라인이 생성한 대용량 5대 산출물(슬라이드, 대본, 과제, 노트, 퀴즈)은 asyncpg를 통해 FastAPI에서 직접 DB에 저장하여 Spring 서버의 불필요한 직렬화/역직렬화 오버헤드를 차단했습니다.
