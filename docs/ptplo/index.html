서버 구성

인증·결제·DB는 Spring에 두고, AI는 Python이 필요해서 FastAPI를 추가했다. 책임을 나누려고 서버를 갈라 두었다.

  • 프론트 — 학습 UI
  • Spring — 인증, 결제, DB 접근
  • FastAPI — AI 파이프라인

Modal GPU 서빙

Qwen3.6-27B를 Modal GPU에 올리고 vLLM으로 돌렸다. 슬라이드, 퀴즈, 노트, 과제를 같이 뽑았다.

462s 순차 → 120s 병렬

클라우드 API는 폴백이다. Modal이 실패하면 Gemini 3.5 Flash, 그다음 Sonnet 4.5.

왜 이렇게 짰는지

한 장씩 뽑으면 462초가 걸렸다

강의 하나를 슬라이드 단위로 순차 호출하면 대기 시간이 길었다. vLLM 배치 스케줄링과 산출물 병렬로 120초까지 줄였다.

교재 PDF를 생성마다 모델에 넣으면 근거가 빠졌다

Marker로 텍스트를 뽑고, 품질 게이트에 걸린 페이지만 MinerU로 다시 뽑았다. BGE-M3 dense와 sparse로 Qdrant에 넣은 뒤, 검색 문단을 강의 생성 컨텍스트에 넣었다.

모델이 뼈대까지 정하면 형식이 강의마다 갈렸다

프레임과 난이도는 템플릿이 고정한다. 모델은 {{빈칸}}만 채운다. 나온 HTML은 살균하고 iframe sandbox로 연다.
