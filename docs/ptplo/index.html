소개 개요 속도 교재 형식 운영 흐름 기록

강의 생성 시간

Modal GPU B200에서 15슬라이드 강의 1개를 만들 때, 검증과 음성 합성까지 넣었습니다.

문제

순차로 돌리면 462초

문제 상황

슬라이드를 한 줄로 뽑고, 검증과 TTS까지 같은 강의에 붙이면 462초가 걸렸습니다.

원인

  • 15장을 순차로 할당하면 GPU가 비는 구간이 생김
  • 검증·음성 합성이 끝난 뒤에야 강의 1개가 완성됨

영향

다음 강의에 못 넘어갑니다.

한 일

vLLM으로 슬라이드를 병렬 할당

환경

  • Modal GPU B200, Qwen3.6-27B, vLLM
  • 대상: 강의 1개, 15슬라이드
  • 포함: 내용 검증, 음성 합성

결과

같은 범위로 120초.

측정

항목순차vLLM 병렬

소개 개요 화면 속도 교재 형식 운영 흐름 기록

교재 PDF → 검색 근거

생성 때마다 PDF를 모델에 넣으면 느리고, 스캔·수식 페이지에서 근거가 빠집니다.

문제 1

원본 PDF를 매 요청에 넣음

문제 상황

강의·시험 프롬프트에 책 전체를 실으면 토큰과 시간이 같이 늘어납니다.

원인

관련 문단만 고르는 인덱스가 없습니다.

문제 2

한 OCR 엔진으로는 페이지 타입이 갈림

문제 상황

텍스트 레이어가 있는 페이지와 스캔 페이지가 한 파일에 섞입니다.

원인

실패한 페이지를 그대로 임베딩하면 검색이 엉뚱한 문단을 가져옵니다.

한 일

왜 Marker / MinerU / Qdrant인가

  • 페이지를 분류한 뒤 Marker로 추출
  • 품질 게이트를 통과하지 못한 페이지만 MinerU로 다시 추출
  • 후처리(머리말·표·수식) 후 섹션 단위로 자름
  • BGE-M3로 dense 1024차원과 sparse를 같이 만들어 Qdrant에 저장
  • 검색은 둘을 병렬로 돌린 뒤 한 리스트로 합쳐 강의 컨텍스트에 넣음

흐름

  1. PDF
  2. 페이지 분류
  3. Marker 추출
  4. 품질 게이트
  5. 실패 시 MinerU
  6. 청킹
  7. BGE-M3
  8. Qdrant

강의 생성은 이 인덱스를 조회합니다. 시험·노트도 같은 문단을 근거로 씁니다.

소개 개요 화면 속도 교재 형식 운영 흐름 기록

슬라이드 형식

모델이 HTML 뼈대까지 만들면 같은 과목인데도 강의마다 레이아웃이 달라집니다.

문제

생성이 디자인까지 가져감

문제 상황

요청마다 제목 크기, 코드 블록, 여백이 바뀌었습니다.

원인

모델에게 슬라이드 전체를 맡기면 형식 제약보다 문장 생성이 이깁니다.

영향

16종 강의 템플릿을 써도 화면에서 같은 제품으로 안 보입니다.

한 일

템플릿이 뼈대, 모델은 칸

결정

  • 프레임과 난이도는 코드가 미리 고정
  • 모델은 {{빈칸}}만 채움
  • 나온 HTML은 서버에서 하이라이트하고 살균
  • 화면은 iframe sandbox. 스크립트만 허용

예

{
  "category": "code",
  "title": "{{핵심_개념}}",
  "narration": "{{설명_200~360자}}"
}

GPU 장애와 음성

양산은 Modal GPU입니다. GPU가 죽으면 생성이 전부 멈춥니다. 음성은 텍스트 모델과 다른 호출입니다.

문제

Modal이 내려가면 강의 생성이 끝

문제 상황

주 엔진을 GPU 한 줄에만 두면 그 줄이 실패하는 순간 파이프라인이 멈춥니다.

한 일

  • 주 경로: Qwen3.6-27B on Modal GPU
  • 실패 시 Gemini 3.5 Flash → Sonnet 4.5
  • API 키는 테스트와 이 폴백에만 사용

폴백은 양산을 대체하려고 둔 것이 아닙니다. GPU가 죽었을 때 빈 화면을 안 주려고 둔 줄입니다.

음성

Qwen3-TTS voice cloning

흐름

  • 슬라이드가 나온 뒤 대본을 만듦
  • 참조 음성과 대본으로 voice cloning
  • 결과를 음성파일로 저장

인식

학생 음성 질문은 Qwen3-ASR이 텍스트로 바꿉니다.

서버 경계

왜 FastAPI를 따로 뒀는가

LangGraph, OCR, 임베딩, GPU 호출을 Java 한 프로세스에 넣지 않으려고 Python 서버를 추가했습니다. 인증·결제·DB 트랜잭션은 Spring에 남겼습니다.

호출 순서

학습 요청은 Spring이 권한과 상태를 만든 뒤 FastAPI 생성 파이프라인이 이어받습니다. 채점 결과만 Spring으로 콜백합니다.
